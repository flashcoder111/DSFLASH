# Open Source Model Blog — 前端设计说明

**状态：** 已确认  
**适用仓库：** `flashcoder111/DSFLASH`  
**目标域名：** `deepseekv4flash.com`  
**语言：** 英文（首发版本）  
**关联文档：** [PRD.zh-CN.md](./PRD.zh-CN.md)

## 1. 设计目标

新站应呈现为独立、可信、易阅读的开源模型资讯出版物，而不是旧 DSFLASH 的产品页、控制台或营销落地页。

已确认采用以下混合方向：

- 借鉴内容卡片站的**内容发现能力**：首页可快速浏览多个更新、专题与模型相关内容。
- 借鉴简洁模型博客的**阅读克制感**：文章、专题和列表页以留白、标题、日期、摘要和清晰来源信息为主。
- 不复刻任何参考站的品牌、页面布局、文案、图像或组件；所有视觉和内容均为本站原创实现。

设计应帮助用户在几秒内回答三个问题：这是什么站、最近有什么值得读、这篇内容依据什么来源。产品站链接仅作为页脚资源，不抢占编辑内容的注意力。

## 2. 视觉原则

1. **编辑优先。** 标题、摘要、日期、专题与来源优先于装饰、动画和转化组件。
2. **少而可靠。** 图片只服务于理解内容；没有授权素材时，使用文字卡、规格表或站内自制图表。
3. **留白但不空。** 首页承担内容发现，文章页承担深度阅读；两者不使用 SaaS 仪表盘式密集布局。
4. **单一强调色。** 使用克制的蓝色来表示链接、标签和交互状态，不使用多色渐变、荧光效果或营销型大按钮。
5. **链接可识别。** 正文链接、外部链接、焦点状态均需有清晰可见的视觉反馈，不能只依靠颜色。

## 3. 品牌、颜色与排版

### 3.1 品牌表达

- 品牌文字：`Open Source Model Blog`。
- Logo 首发使用纯文字字标；无需在 MVP 阶段设计独立图标。
- Header 与页脚均使用同一品牌名称。点击 Header 品牌返回首页。
- 视觉语气：冷静、研究型、清楚，不做“未来科技”“黑客终端”或大型产品发布会风格。

### 3.2 颜色令牌

| 用途 | 建议值 | 说明 |
| --- | --- | --- |
| 页面底色 | `#FCFCFA` | 近白暖灰，降低纯白眩光。 |
| 主文字 | `#171717` | 标题、正文。 |
| 次级文字 | `#626262` | 日期、摘要、说明。 |
| 细边框 | `#E7E7E3` | 卡片、分割线、表格。 |
| 强调蓝 | `#2563EB` | 链接、标签、键盘焦点与少量图表。 |
| 悬浮背景 | `#F4F7FF` | 链接或卡片悬浮反馈。 |

不使用旧站的深色数据面板视觉。深色代码块仅在文章内容需要展示命令、代码或结构化数据时出现。

### 3.3 排版令牌

- 使用清晰的无衬线字体（优先 `Inter`、`Geist` 或等价系统字体），避免首发混用多种字体。
- 正文桌面端 `18px / 1.7`；移动端 `17px / 1.7`。
- 首页主标题桌面端约 `56–64px`，移动端约 `40–44px`；不使用占满首屏的超大标题。
- 卡片标题桌面端 `20–24px`；文章标题 `44–56px`；列表标题 `28–36px`。
- 元信息、标签和来源数使用 `12–14px`，大小写和间距保持一致。
- 正文单列最大宽度约 `720px`；列表阅读区约 `760–820px`；首页内容容器最大宽度 `1200px`。

## 4. 全局框架

### 4.1 顶部导航

桌面端为单行、白底、细底边框的紧凑 Header：

```text
Open Source Model Blog       China Models   Global Models   GitHub Radar   Topics   Comparisons
```

- 品牌在左，导航链接紧随其后或在同一行居中区域；不放 `Home`，品牌本身返回首页。
- `China Models` 与 `Global Models` 是读者熟悉的模型地区入口；首发分别以 DeepSeek/Qwen/Kimi 和 Gemini/Claude/GPT 为主。`GitHub Radar` 是经审核的开源项目雷达；`Topics` 承担概念型专题。三者不得混为一个下拉目录。
- Header 不加入搜索框、语言切换、登录、下载按钮、聊天入口或产品 CTA。
- 滚动时可保持轻量 sticky；不得遮住文章标题或造成明显阴影。
- 当前路由以文字色、细下划线或底部边线识别，不使用大面积填充按钮。

### 4.2 页脚

桌面端采用四栏文字型页脚，移动端按栏目纵向排列：

```text
Brand | Open Models | Explore | About
```

- **Brand：** 站点一句话说明、联系邮箱、版权。
- **Open Models：** DeepSeek、GLM、Kimi、MiniMax、Hunyuan、查看全部模型。
- **Explore：** Topics、Model Library、Comparisons、Latest Articles。
- **About：** About、Editorial & Sources Policy、Privacy、Terms、Contact。
- `DeepSeek V4 API ↗` 是唯一指向 `https://deepseekv4pro.com/` 的产品链接。它以普通文字链接呈现，位于页脚一次，不做按钮、不做卡片、不在正文重复。

### 4.3 公共内容组件

| 组件 | 用途与规则 |
| --- | --- |
| `ArticleCard` | 标签、标题、日期、摘要；可选自制/授权缩略图。整卡可点击，键盘可访问。 |
| `FeaturedArticle` | 首页仅一个主要推荐内容；左图右文（移动端上下排列）。 |
| `ArticleListItem` | 用于归档、专题、模型页：标题、日期、摘要和可选来源数，项目之间用细线分隔。 |
| `TopicPill` | 简短主题标签，例如 World Models；仅作分类导航，不能堆叠长关键词。 |
| `SourceBadge` | 展示“X sources”或“Sources reviewed”，链接到文章内来源区。 |
| `ModelMeta` | 模型页/比较页的结构化字段，如发布者、许可、上下文、最后核查日期。 |
| `EmptyState` | 无内容时说明该栏目正在建立，给出相关专题或模型页链接，不生成虚假卡片。 |

## 5. 页面设计

### 5.1 首页 `/`

首页承担内容发现，不应做成单一文章归档，也不应变成营销型 Hero。

页面顺序：

1. Header。
2. 简短编辑定位：`Independent model research` 眉题、主标题、两行以内的说明文案。
3. 热门专题文字链接：World Models、AI Agents、Long Context、AI Coding、Loops。
4. 一个 Featured Article：自制/授权图表或官方授权素材 + 标题、日期、摘要、来源数。
5. 最新文章网格：桌面端三列、移动端一列；首屏后展示 6–9 篇即可。
6. `Latest research notes` 文字列表：用分割线呈现标题、日期和来源数，提供更轻的“快速扫读”入口。
7. 页脚。

首页卡片不是每张都必须有图片。无图文章使用更轻的文字卡，避免为了填满网格而使用不明授权图片。

### 5.2 文章页 `/articles/[slug]`

文章页遵循单列、安静、可核查的阅读体验：

1. 面包屑（可选，层级不超过两级）。
2. 专题标签、文章标题、摘要、发布日期与最后核查日期。
3. 发布日期、最后核查日期与阅读时长；首发不显示个人作者署名，也不得伪造个人作者身份。
4. 可选封面图，仅限已记录授权的官方素材或自制图。
5. 正文主体，最大宽度约 `720px`；段落、引用、表格、代码块和图表均保证可读。
6. `Sources` 区：按官方、论文、第三方评测等清晰列出真实原始链接。
7. `Related reading`：2–3 篇真正相关的站内文章，不插入固定产品推广。
8. 页脚。

文章正文不放固定的 DeepSeek V4 CTA。若文章本身讨论 DeepSeek V4，编辑可在事实相关的位置自然引用产品页；此类链接需由人工审核，不能成为模板字段。

### 5.3 专题页 `/topics`、`/topics/[slug]`

- `/topics` 以简洁的专题索引开始：名称、短说明、最近更新时间、文章数量。
- `/topics/[slug]` 顶部说明该专题覆盖范围与编辑口径，下方采用 `ArticleListItem` 的单列列表。
- 专题页用文字和少量抽象自制图形区分，不为每个专题制作大海报。

### 5.4 地区模型页与 GitHub Radar `/china-models`、`/global-models`、`/github-radar`

- `China Models` 与 `Global Models` 分别以模型卡片列出对应地区的核心模型；模型库总目录仍在页脚和地区页内可访问。开权重状态在具体模型页标注，而不是作为是否进入 Global Models 的唯一门槛。
- `GitHub Radar` 使用文字型项目列表，展示项目类别、为什么值得关注、许可证和最后观察日期。
- Radar 不复制 GitHub Trending 的简介或 star 数；每个项目都要由编辑确认其与开源模型生态的关系。

### 5.5 模型库 `/models`、`/models/[slug]`

- `/models` 用模型/发布方条目组成轻量目录，可按发布方或能力方向分组；不做模拟榜单。
- `/models/[slug]` 首先展示可验证的模型信息卡（发布方、版本、许可、官方链接、最后核查日期），再展示相关新闻、更新和相关对比。
- 对未知或暂未核实字段显示“Not verified”，不以空值或推测填充。

### 5.6 模型对比 `/compare`、`/compare/[slug]`

- `/compare` 使用文本列表或少量卡片，标题需清楚说明比较对象。
- `/compare/[slug]` 先说明比较范围与更新时间，再用响应式表格展示可引用维度（定位、上下文、许可、价格/可用性、公开评测等）。
- 小屏表格需可横向滚动，并保留行标题；不能把重要信息截断为图片。

### 5.7 政策页与 404/410

- About、Editorial Policy、Privacy、Terms、Contact 使用 `720px` 左右的文本阅读列，结构简洁。
- 404 明确说明页面不存在，并提供首页、专题、模型库和最新文章入口。
- 410 为旧站已退役内容，提供简短说明；不得自动跳到首页。

## 6. 图片与图表规范

- 可用：有明确授权记录的官方媒体、官方 Logo（在合理必要范围内）、站内原创规格卡、时间线、比较图、流程图。
- 禁用：X/Reddit 作者图片、竞对页面截图、未经授权的搜索图片、仅为美观生成却暗示真实事件的“新闻配图”。
- 自制图表要在内容记录中保存生成文件、alt text、适用文章与授权/来源说明。
- 所有信息性图片必须有具体 alt text；纯装饰图可使用空 alt。
- 图片尺寸优先采用 `16:9` 或 `4:3`，避免同一网格中比例杂乱。

## 7. 响应式与可访问性

- 设计从移动端开始验证；断点建议为 `640px`、`768px`、`1024px`。
- 小于 `768px` 时，Header 导航可折叠为菜单；Featured Article 和文章网格改为单列；页脚栏目纵向排列。
- 不依赖 hover 才能获知链接、来源或卡片是否可点击；所有交互均支持键盘操作与清晰焦点环。
- 普通正文与背景对比度至少满足 WCAG AA；蓝色链接需同时使用下划线、字重或其他非颜色提示。
- 保证触控目标至少约 `44 × 44px`；避免横向溢出（比较表的受控横向滚动除外）。
- 尊重 `prefers-reduced-motion`；首发不需要复杂动画。

## 8. SEO 与性能的前端约束

- 公开内容采用服务端渲染或静态再生成，保证标题、摘要、来源和正文在初始 HTML 中可见。
- 每个页面只有一个 H1；卡片标题按页面层级使用 H2/H3。
- 文章图像使用 Next.js `Image`、明确尺寸和 lazy loading；首屏唯一重点图可优先加载。
- 不引入沉重的轮播、视频背景、弹窗广告、聊天挂件或全站客户端状态库。
- 公共页必须使用唯一 canonical；后台、草稿和 Preview 环境为 `noindex`，详见 PRD。

## 9. 实现验收

- [ ] Header 仅包含品牌、Topics、Model Library、Comparisons；没有产品 CTA、搜索或登录入口。
- [ ] 首页同时具备精选内容、文章卡片和文字型最新列表，但视觉不拥挤。
- [ ] 文章页正文宽度、字体与行高适合长文阅读，并有清晰 Sources 区。
- [ ] 所有图片均符合授权与 alt text 规范；无图文章在设计上仍完整。
- [ ] 手机端导航、卡片、表格与页脚均可操作且不横向溢出。
- [ ] 页脚中只出现一次 `DeepSeek V4 API ↗`，并链接至 `https://deepseekv4pro.com/`。
- [ ] 页面不包含旧产品站的深色面板、聊天、价格、下载或 API Key 组件。

## 10. 实施顺序

1. 建立新的全局样式令牌、字体、公共 Header/Footer 和页面容器。
2. 先实现静态的首页、文章页、Topics、Model Library、Comparisons 与政策页，使用审核过的示例内容验证布局。
3. 接入 Supabase 的已发布内容读取，再实现后台与草稿工作流。
4. 最后接入 sitemap、结构化数据、301/410 映射、Vercel Preview 验收与正式迁移。
